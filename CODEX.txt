# 프로젝트 진행 상태

프로젝트 경로: /app/logplus-platform
마지막 업데이트: 2026-09-27
현재 목표: 4인 협업에서 운영·LLM 인프라와 애플리케이션 개발 책임을 분리
현재 상태: React/Vite 웹, FastAPI·MariaDB API, Git push 후 Docker builder, Ollama 분석 파이프라인의 책임 경계를 확인했다. 사용자 1명은 서버·LLM 런타임을 맡고, 나머지 3명은 API/DB, 웹/UX, 빌드·QA·AI 기능으로 나누는 안을 정리했다.

완료된 작업:
- `docs/END_TO_END_ARCHITECTURE.md`에 구성도, sequence diagram, API·데이터 경계, 검증 근거, 운영 보완점을 기록
- `docs/END_TO_END_ARCHITECTURE.pdf`에 같은 흐름을 4페이지 PDF로 추가
- 현재 운영 경로(`/app/logplus-platform`), `/repos`, `projects`, `logs`, MariaDB 역할을 문서화
- 실제 구현과 샘플 UI 영역(통계 카드·알림·차트)을 구분
- 권장 4인 역할: 사용자=인프라·배포·LLM 런타임, 팀원 2=API·DB·인증, 팀원 3=웹·UX, 팀원 4=builder·QA·AI 기능 평가
- 운영 서버 변경은 사용자 승인으로 제한하고, 팀원은 로컬·스테이징·mock 환경에서 독립 개발하도록 경계를 정함

이번 작업에서 변경한 파일:
- `CODEX.txt`

실행한 테스트와 결과:
- `pwd -P`: `/app/logplus-platform` 확인
- `git -c safe.directory=/app/logplus-platform status --short`: 기존 `CODEX.txt` 수정 및 아키텍처 관련 미추적 파일 확인, 보존
- README·구조 문서·웹 package.json/package-lock·API requirements를 읽어 역할 경계를 확인
- 코드 변경이 없는 역할 설계 작업이므로 빌드·서비스 재기동은 실행하지 않음

현재 알려진 문제:
- 프론트 전체 `npm run build`는 기존 TypeScript 오류로 실패한 기록이 있다.
- Vite는 5174 단일 포트를 사용하도록 했지만 기존 프로세스가 남으면 기동 포트가 흔들린 이력이 있다.
- 최종 probe에서 `curl http://127.0.0.1:8000/health`와 `curl -I http://127.0.0.1:8080/git/info/refs`가 `connection refused`로 실패했다. 앞선 probe와 운영 로그에는 성공 기록이 있으나 현재 프로세스 상태는 미확정이며 재기동하지 않았다.
- 로그인·로그·AI API는 요청 body의 users_id/team_id에 의존하며 서버 세션/토큰이 없다.
- 비밀번호 해시, CORS 제한, DB 비밀값 환경변수화, builder queue/lock이 추가로 필요하다.
- 대시보드 통계·알림·예외 차트는 현재 샘플 데이터다. Docker 컨테이너도 외부 앱 화면이 아니라 실행 로그 수집용이다.

다음 작업:
- 팀원별 담당 모듈, PR 승인자, 로컬·스테이징 실행 절차를 문서화
- builder·로그·AI 분석을 포함한 통합 테스트와 CI를 팀원 4가 먼저 정리
- 프론트 TypeScript 오류와 인증·비밀값·로그 접근 제어를 담당자별 작업으로 분리

주의사항:

- 이번 작업에서는 push·hook 재실행 같은 외부 상태 변경을 하지 않았다.
