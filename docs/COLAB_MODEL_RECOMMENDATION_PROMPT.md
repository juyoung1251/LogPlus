# Colab 모델 추천 요청 프롬프트

아래 코드 블록을 Gemini에 복사해서 사용한다. 실제 소스 확인일: 2026-10-04.
현재 GPU·구독 혜택·추론 성능은 사용자 계정에서 확인하지 않았다.

```text
나는 Gemini Pro를 유료로 이용하고 있고, Google Colab에서 내 프로젝트에 사용할 오픈 가중치 LLM을 시험하려고 한다. 아래 프로젝트 정보를 바탕으로 적합한 모델과 실행 방식을 추천해 줘. 한국어로 답하고, 답변 시점의 공식 문서와 공식 모델 카드·배포 저장소를 검색해 출처와 확인 날짜를 표시해 줘.

[프로젝트: LogPlus]
- 사용자가 Git push하면 Docker로 프로젝트를 빌드·실행하고, 의존성 설치/빌드 로그(LIB)와 실행 로그(RUN)를 저장하는 서비스다.
- 웹은 React/TypeScript/Vite, API는 Python/FastAPI, DB는 MariaDB다.
- 빌더는 Python, Node.js, Java(Maven/Gradle), C/C++ 프로젝트를 처리한다.
- AI의 주된 역할은 로그와 스택트레이스를 분석해 한국어로 장애 원인, 근거 로그, 해결 방법을 작성하는 것이다.
- AI 결과는 DB 메타데이터와 TXT 파일로 보관하고 웹에 표시한다. 결과 저장이 자동 학습을 의미하지는 않는다.

[현재 AI 구현]
- Ollama 기본 모델명은 qwen2.5-coder:7b다. 환경 변수로 변경할 수 있다. 실행 중인 서버의 실제 모델·GPU·양자화 설정은 아직 확인하지 않았다.
- API는 /v1/chat/completions에 model, messages, stream=false, temperature=0.2, top_p=0.8, max_tokens=1200을 전달한다. 호출 timeout은 120초다.
- 로그를 규칙으로 추려 최대 6000자까지 입력한다. 이는 6000토큰이라는 뜻이 아니다. 현재 소스 주석의 컨텍스트 기준은 4096이며 실제 서버 설정은 미확인이다.
- 전처리는 연결 실패, 메시지 필드 불일치, JSON 파싱 오류, HTTP 4xx/5xx, 오류 처리기 미설정, 클래스 로딩 실패, OOM·프로세스 종료 등의 대표 오류와 주변 문맥을 보존한다.
- 답변은 '## 원인', '## 해결 방법' 두 섹션만 사용하고 오류 그룹별 심각도·근거·조치를 작성한다. 기술 식별자는 원문을 유지한다.
- 한국어 비중이 낮으면 별도 한국어 재작성 호출을 하므로 추가 지연이 생길 수 있다.
- 대표 사례만 남기는 전처리 때문에 전체 로그의 정확한 발생 횟수와 일부 근거는 사라질 수 있다. 모델 교체로 복구할 수 있다고 가정하지 마라.

[데이터 확장 상태]
- 사람이 검증한 원인·해결책을 보관할 ai_training_examples SQL이 있다. 상태는 pending/approved/rejected다.
- 현재 ORM, 사례 저장·승인 API, 화면, RAG, 파인튜닝은 연결되지 않았다. 승인 사례 수와 품질도 현재 확인되지 않았다.
- 먼저 기본 추론 성능을 비교하고, 검증 사례를 모은 뒤 RAG와 LoRA/QLoRA 필요성을 판단하고 싶다.

[추천 요청]
1. 내 정확한 Google AI 요금제·지역·유료 구독 상태에 따른 Colab 혜택과 컴퓨팅 단위 확인 방법을 설명해 줘. Gemini 앱 구독, Colab GPU 이용, Gemini API 과금을 구분하고, 특정 GPU 배정이나 무료 API 사용을 보장하지 마라.
2. Colab에서 실제 GPU와 VRAM을 확인하는 방법을 먼저 알려 줘. GPU 정보가 없으면 T4 16GB, L4 24GB, A100 40GB를 가정한 조건별 추천을 제시하되 배정을 보장하지 마라.
3. 로그 장애 분석·한국어 설명·근거 준수·속도·메모리를 기준으로 후보 모델을 최대 3개 골라 줘. 코딩 벤치마크 점수만으로 선택하지 마라. 현재 qwen2.5-coder:7b를 비교 기준으로 포함해 줘.
4. 비교 표에는 정확한 모델명, 공식 Hugging Face repo ID, Ollama 사용 시 실제 존재하는 정확한 태그, Instruct/추론형 여부, 파라미터 수, 라이선스, 실행 엔진, 지원 양자화 방식, GPU별 적합성을 표시해 줘. 없는 태그를 만들지 말고 미지원·미확인은 표시해 줘.
5. 메모리는 모델 가중치뿐 아니라 KV cache·런타임 여유분을 포함해서 추정해 줘. batch=1, 입력은 로그 6000자에 시스템/사용자 프롬프트 추가, 출력 상한 1200토큰을 기준으로 삼고 실제 토큰 수를 측정해야 함을 설명해 줘. 추론과 QLoRA 학습 메모리를 구분해 줘.
6. T4에서 우선 시험할 모델 1개와 VRAM 여유가 있을 때 비교할 모델 1개를 명확히 골라 줘. 추론형이면 내부 추론 토큰과 최종 출력 예산, 응답 형식과 지연 영향을 확인해 줘. 측정하지 않은 속도와 정확도는 추정이라고 밝혀 줘.
7. 선택한 첫 모델을 실행할 최소 Colab 셀을 순서대로 작성해 줘: GPU 확인 → 검증된 의존성 버전 설치 → 모델 로딩 → 비밀정보를 제거한 예제 로그 분석 → 경과 시간·최대 GPU 메모리 측정. T4 호환 dtype·양자화를 쓰고 HF repo ID와 Ollama 태그를 혼용하지 마라. 인터넷에 운영 로그·비밀번호·토큰을 보내는 예제를 만들지 마라.
8. 익명화한 동일 로그와 동일 프롬프트로 기존 모델과 후보를 비교할 평가표를 제시해 줘. 원인 정확성, 서로 다른 오류 분리, 근거 인용, 환각, 한국어·형식 준수, 원문 대비 전처리 누락, 응답 시간, peak VRAM을 평가하고 정답은 사람이 검증하도록 해 줘.
9. 승인 사례 RAG와 LoRA/QLoRA를 언제 선택할지 설명해 줘. 저장된 AI 답변을 그대로 정답 데이터로 쓰지 말고, 검증 사례가 부족하면 파인튜닝을 서두르지 마라.
10. Colab에서의 수동 실험과 운영 서버의 상시 추론을 구분해 줘. 현재 FastAPI 호출 계약을 유지하려면 무엇을 확인해야 하는지 간단히 설명하고, 런타임 종료·사용 한도·정책을 고려한 운영 대안도 제시해 줘.

답변은 '우선 추천 → 후보 비교 표 → Colab 실행 셀 → 평가 방법 → RAG/학습 판단' 순서로 작성해 줘. 불확실한 항목은 단정하지 말고 확인 방법을 함께 알려 줘.
```
